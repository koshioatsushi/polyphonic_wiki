# 04 — Polyphonic answering

A polyphonic answer should not immediately produce a consensus. It should expose the voice structure first.

## Required answer shape

```markdown
## P1 — current stance
...

## P1.5 — AI-mediated contributions
...

## P2 — field / relational voices
...

## P3 — public anchors
...

## Tensions
...

## Missing voices
...

## Provisional answer
...

## What would change this answer
...
```

## Rules

1. Do not treat `P1.5` as factual evidence.
2. Do not generalize from `P2` without naming role, situation, and sample weakness.
3. Do not let `P3` erase situated context.
4. Name absent voices before giving recommendations.
5. Prefer “provisional synthesis” over “final conclusion.”

## Bad pattern

> The evidence suggests that auditability is the key issue.

## Better pattern

> P1 frames the issue as operational ownership. P1.5 raised auditability as a rival frame. P2 currently supports ownership more strongly, but only from one enterprise user. P3 shows audit and accountability pressure, but the public anchors are broad rather than product-specific. Missing voice: compliance buyer. Provisional answer: test ownership language and auditability language separately in the next three field conversations.
